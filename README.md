# 创业社区入退驻的地址托管与来件交付

本仓库保存该业务的合成登记资料、原始变更资料、来件转寄承运台的本地协议服务，以及入退驻业务 HTTP 服务。所有机构、人员、金额和文书均为虚构，不连接真实业务系统。

## 运行环境

使用 Node.js 22.23.4。没有第三方 npm 依赖，package-lock.json 锁定当前依赖清单。

```bash
npm ci --ignore-scripts
npm run build
npm test
npm run start:partner   # 外部承运台协议服务，4317
npm run start:app       # 入退驻业务服务，4318
```

合作方默认监听 4317 端口，GET /health 可查询存活状态。PORT 可更换端口，PARTNER_STATE 可指定持久状态文件，默认 .local/partner.json。停止进程后用同一状态文件启动会保留合作方流水。

业务服务默认监听 4318 端口，环境变量：`PORT`、`APP_STATE`（默认 .local/app.json）、`CARRIER_URL`（默认 http://127.0.0.1:4317）、`SEED_FILE`（默认使用 fixtures/records.json 播种，置空则从空状态启动）。首次启动会把合成资料登记为**未核准**的初始状态：代表权与入驻仍是草案，来源变更进入待处理队列，不会自动变成已批准决定。

也可以使用 Docker 启动合作方：

```bash
docker build -t community-exit:local .
docker run --rm -p 4317:4317 community-exit:local
```

容器要保留状态时，将可写目录挂载到 /app/.local；该目录需允许容器 node 用户写入。测试使用临时目录与随机本地端口，可独立运行。npm test 同时验证资料关系、合作方协议与业务规则（16 项检查）。

## 业务服务要点

业务服务把企业搬离拆成可逐项核对的责任，而不是简单的“已退驻”标签：

- **企业授权**：代表权与授权领取人分离；授权有期限、材料范围与转交限制；代表权更换后旧授权须重新核实，已合法领取的事实保留；申请人不能自行核准本人身份或争议解除。
- **入退驻**：入驻由运营确认签约主体与授权领取人；退驻分别结束空间使用、人员进出、地址托管与未结来件，`GET /exits/:id/overview` 一次查清新旧责任。
- **门禁状态**：凭证发放锚定企业服务；归还确认期间立即冻结新入场，所有入场尝试（含拒绝）留痕。
- **收取转寄**：前台登记件号、收件主体、到达时间与封装状态；扫描面单仅存引用不公开全文；挂号通知须代表本人签收；转寄受理未明时保留原件责任且禁止现场领取，实际转寄后的撤销只作拦截申请。
- **押金结清**：费用与争议暂扣逐项登记、只冻结争议金额；退款受凭证归还与自由余额约束；退押金不清空未完成转寄责任。
- **最小权限**：前台只能访问交付所需视图，企业只能查自己的件，争议复核有独立记录与独立角色。

## 资料

fixtures/records.json 是业务原始资料，sourceChanges 保存后续收到的变更或申请，均没有自动导入成已批准决定。fixtures/relations.json 声明登记资料的关联字段，docs/data.md 解释计量和身份语义。fixtures/partner.json 定义合作方接口名称及字段。support/peer.mjs 提供合作方行为，docs/partner.md 是实际协议；src/ 是业务服务实现，docs/api.md 是业务接口说明，docs/exit-walkthrough.md 串联代表权更换、保留地址服务与旧件转寄未明的完整退驻线；tests 检查协议、资料关系与业务规则。
